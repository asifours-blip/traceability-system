# 教学项目边界与生产整改优先级

## 当前定位

本仓库是 FISCO BCOS 农产品溯源**毕业设计/教学项目**。它展示三角色流转、链上 CID 存证、IPFS 文件引用、模拟 IoT 看板和离线后端单测；不宣称已经具备生产部署、真实传感器接入或生产级身份安全。

## 不能当作生产鉴权的部分

当前身份信号是客户端发送的 `address` 请求头，后端检查其格式和部分业务地址关系。请求头可以被任意客户端伪造，因此它不是 JWT、签名认证或会话认证，也不能作为真实用户身份的安全边界。

教学演示中它足以让流程可见；生产设计必须以服务端可验证的身份凭据替代，并把资源所有权和角色权限绑定到经过验证的主体，而不是请求头文本。

## 生产整改优先级

### P0：身份与授权边界

1. 引入服务端验证的身份认证方案，例如 OIDC/JWT 或基于钱包签名的 challenge-response；令牌/签名必须绑定受控的 subject 与过期时间。
2. 在所有写接口统一执行认证、角色授权和资源所有权校验；鉴权失败使用语义正确的 HTTP 401/403，而不是 HTTP 200 + 业务错误体。
3. 为认证绕过、跨角色越权、篡改 address header 与过期凭据新增自动化负向测试。

### P1：依赖与交付链路

1. 为 Spring Boot、Vue、FastJSON、Solidity 编译器和本地 JAR 依赖建立可审计的升级/替换清单；升级前先做兼容性与漏洞评估，不把“版本变新”误当成安全修复。
2. 移除或替换难以复现的 `systemPath` 本地 JAR 依赖，使用受版本锁定和来源可验证的依赖管理方式。
3. CI 除 `mvn test` 与前端 lint 外，补前端 production build、依赖漏洞扫描/SBOM 与构建产物保存。

### P2：合约与运行验证

1. 为 `Trace` 合约增加单元/集成测试并在 CI 执行，覆盖角色限制、状态流转、失败交易与 ABI 兼容性；当前 Mock WeBASE 后端测试不等于合约测试。
2. 在隔离的 FISCO/WeBASE/IPFS 环境增加端到端 smoke test；保留不连外部服务的快速单测层。
3. 明确 IoT 数据为模拟数据；若接入真实设备，增加设备身份、数据完整性、时钟与异常读数处理。

## 不在本轮实施的原因

这些整改会改变安全模型、依赖图和部署方式，属于独立工程项目，而不是 README 文案修补。公开仓库先把能力边界和优先级写清楚，避免把教学实现包装成生产交付。
