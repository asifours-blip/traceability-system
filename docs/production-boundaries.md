# 教学项目边界与生产整改优先级

## 当前定位

本仓库是 FISCO BCOS 农产品溯源**毕业设计/教学项目**。它展示三角色流转、链上 CID 存证、IPFS 文件引用、模拟 IoT 看板和离线后端单测；不宣称已经具备生产部署、真实传感器接入或生产级身份安全。

## 身份认证现状与剩余缺口

身份已从客户端 `address` 请求头改为服务端账号体系：用户名 + BCrypt 密码登录，服务端签发 256 位随机 token（库里只存 sha256，可过期、可撤销）；拦截器按 token 解析账号，把账号绑定的链上地址作为唯一签名地址，按账号角色返回 401/403。私钥仍托管在 WeBASE-Front，后端对其有完全签名权，这是信任 WeBASE 部署本身的前提。

仍不宣称生产级：登录限流已按账号 + IP 做了失败次数统计与锁定（见下），但没有审计日志；没有 MFA、密码修改与找回；过期会话不自动清理；新用户链上地址由管理员手填，未对接 WeBASE 私钥管理接口；CORS 仅放行本地开发源，部署需另配 HTTPS。

## 生产整改优先级

### P0：身份与授权边界

1. 已完成：服务端账号 + 不透明 token 会话，签名地址只来自服务端绑定地址；接口级角色鉴权返回 403；删除公开注册，停用账号由管理员签名撤销链上角色。
2. 已完成：`AuthIntegrationTest` 等负向测试覆盖伪造 address 头、无/过期/撤销 token、错误密码、跨角色 403、非 ADMIN 管理用户、请求体夹带地址。
3. 已完成：登录限流与失败锁定（按账号 + IP，滑动窗口，429 + `Retry-After`，见 `LoginRateLimiterImpl`）。待做：审计日志、密码修改与找回；如需去托管化，可改为钱包签名 challenge-response，让私钥留在用户侧。
4. 已完成（后端规则）：批次归属与交接对象、字段校验、链下只追加更正、消费者只见公开字段、公开文件只按链上绑定读取，见 [business-flow.md](business-flow.md)。
5. 待做：「只有被指定的分销商/零售商能写下一阶段」目前只在后端强制，持角色账户直接调用合约可以绕开；要做成链上强制需改合约并重新部署。WeBASE-Front 必须只对后端开放，否则任何能访问它的人都能用托管私钥签名。

### P1：依赖与交付链路

1. FastJSON 已移除；为 Spring Boot、Vue、Solidity 编译器和本地 JAR 依赖建立可审计的升级/替换清单；升级前先做兼容性与漏洞评估，不把“版本变新”误当成安全修复。
2. 移除或替换难以复现的 `systemPath` 本地 JAR 依赖，使用受版本锁定和来源可验证的依赖管理方式。
3. CI 除 `mvn test` 与前端 lint 外，补前端 production build、依赖漏洞扫描/SBOM 与构建产物保存。

### P2：合约与运行验证

1. 为 `Trace` 合约增加单元/集成测试并在 CI 执行，覆盖角色限制、状态流转、失败交易与 ABI 兼容性；当前 Mock WeBASE 后端测试不等于合约测试。
2. 部分完成：`scripts/local-chain/` 在隔离的 FISCO BCOS + WeBASE-Front 上跑合约全流程与反例（手动执行，未进 CI），`files-e2e.sh` 额外接了真实本地 kubo；交易结果分为成功/失败/未知并可查证（`docs/tx-lifecycle.md`）。保留不连外部服务的快速单测层。
3. 明确 IoT 数据为模拟数据；若接入真实设备，增加设备身份、数据完整性、时钟与异常读数处理。
4. 已完成：MySQL / kubo / 链上标识的备份恢复脚本与一次本机真实恢复演练，见 [backup-restore.md](backup-restore.md)。待做：生产规模下的增量备份（binlog）、kubo 热备份或换成支持热备份的存储、定期演练排期。

## 不在本轮实施的原因

这些整改会改变安全模型、依赖图和部署方式，属于独立工程项目，而不是 README 文案修补。公开仓库先把能力边界和优先级写清楚，避免把教学实现包装成生产交付。
